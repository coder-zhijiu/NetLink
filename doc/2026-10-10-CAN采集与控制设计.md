# CAN 采集与控制（直采直控 + CAN 转以太网）· 设计规格

> 定稿日期：2026-10-10
> 状态：**CAN-M1 + 周期报文已实现（slcan 后端，2026-10-10）**——CanFrame/CanIo/主循环/CanNode 模型/发送报文表/ID 聚合/帧率统计/手动发送面板/CANET 检测全部落地，schema v3；zlgcan（M2）与 CanNet（M3）等硬件到货后实现（枚举分支已入 schema，启动时明确报「未实现」）
> 前置：Modbus 主从模拟（M1/M2）已落地；本设计沿用其架构与既有结论（FrameEvent 报文监视、ConnState 链路状态、退避重连模式）

## 〇、实现纪要（2026-10-10）

- **引擎**：`netlink-core/src/protocol/can/`（mod.rs 主循环 + slcan.rs 后端）。主循环平移 RTU 主机单线程模式，`recv` 等待时长收敛到最近到期帧（空闲 50ms 一拍），命令插队非阻塞收取；IO 错误置「重连中」徽章并 20ms 限速防空转。集成测试走 `FakeCanIo`（`tests/can_master.rs`，6 用例：周期时序/命令插队/聚合/链路状态/serde 兼容/未实现后端拒绝）。
- **实现期补充决策**：① `CanPeriodicFrame` 增加 `id` 行标识（编辑/删除的稳定 key，镜像 Point.id）；② `UsbCan` 增加 `serial_baud`（slcan 串口侧波特率，默认 115200，与 CAN 波特率独立）；③ `Connection.can_nodes` 为并行字段（serde default，v2 工程直接读入，Modbus 路径零改动）。
- **UI**：连接编辑器 UsbCan/CanNet 表单（can_net 可配置可检测但启动报「M3 未实现」）、树内 CAN 节点行（▶/■=暂停周期发送）、发送报文表（CanFrameTable.vue，ID/扩展/远程/DLC/hex/周期/启用/备注 + 行内校验与 Rust 端 validate 同构）、监视器「报文流 / ID 聚合」视图切换、CAN 发送抽屉（含已定义报文一键载入）、`can_rx` 观测经 250ms 推送链路（帧率徽章/悬浮）。
- **验证**：cargo 全绿（core 40 测试，其中 CAN 6 集成 + 4 编解码单测）；浏览器 mock 冒烟（演示工程含 CAN 连接，周期发送/心跳聚合/手动发送/编辑校验/表单全通过）。真实 slcan 设备（CANable 等）插上即可用。


## 一、定位

CAN 支持分两条链路，**共享同一套 CAN 上层逻辑**：

1. **直采直控（USB-CAN）**：USB-CAN 适配器直连总线——被动监听全量报文（直采）+ 手动单帧/周期报文发送（直控）；
2. **CAN 转以太网（ZLG CANET）**：TCP 连接 CANET 网关，网关侧收发 CAN 帧——采集与指令下发与直采完全同构（NetLink 视角里只是换了一个 CanIo 后端）。

两条链路的差异被压在 IO 后端一层：周期发送器、监听聚合、报文监视、总线统计、链路状态全部复用。

## 二、核心决策（2026-10-10 访谈结论）

| # | 决策项 | 结论 |
| --- | --- | --- |
| 1 | 高层协议 | **裸帧优先**：第一版只做帧级收发（ID/DLC/数据/时间戳），不解析上层语义；DBC 信号解码二版再做 |
| 2 | 网关选型 | **周立功 CANET**（CANET-2E 双通道，TCP 透传模式，帧封装协议按官方手册） |
| 3 | 直控形态 | **手动单帧 + 周期发送**；不做协议级应答（完整节点模拟后置） |
| 4 | DBC 解码 | 第二版；第一版报文监视器用 ID + hex + note 展示（与现有监视器同构） |
| 5 | 数据模型 | CAN 连接下无"点表"概念：设备层退化为 **CAN 节点（发送报文组）**，点位层对应 **周期报文定义**；接收侧是运行时聚合（不进工程文件） |
| 6 | 故障注入 | CAN 侧 v1 不做（丢帧/延迟注入架构上可平移 Reply 模式，留后） |

## 三、数据模型扩展（与前端 types.ts 同步）

```
Transport 新增（kind = "usb_can" / "can_net"）：
  UsbCan {
    backend: String,        // "zlgcan" | "candle" | "slcan"（后端见 §四）
    device_index: u32,      // zlgcan 设备号；candle 通道路径序号
    channel: u8,            // CAN 通道号（双通道设备 0/1）
    bitrate: u32,           // 常用档位 125k/250k/500k/1M；zlgcan 内部换算 Timing0/1
    serial_port: Option<String>, // slcan 后端的串口名（其余后端忽略）
  }
  CanNet {
    host: String, port: u16,        // CANET 的 TCP 地址（透传模式端口按手册/设备配置）
    channel: u8,                    // 映射 CANET 的哪路 CAN
    timeout_ms: u32,                // 读超时（帧间隔判读 + 断线判据）
  }

Can 节点（挂在 CAN 连接下，替代"设备"层）：
  CanNode { id, name, enabled, frames: Vec<CanPeriodicFrame> }

周期报文定义（替代"点位"层）：
  CanPeriodicFrame {
    frame_id: u32,          // 0x000~0x7FF 标准 / 0x00000000~0x1FFFFFFF 扩展
    extended: bool,
    remote: bool,           // 远程帧（数据域为空）
    data: Vec<u8>,          // ≤8；dlc = data.len()
    period_ms: u32,         // 0 = 不自动发（仅保存定义，手动发送面板可选它）
    enabled: bool,
    note: Option<String>,
  }

接收聚合（运行时，不进工程文件）：
  CanRxStat { frame_id, extended, count, avg_period_ms, last_data, last_ts }
```

工程文件 schema_version 升到 3（新增枚举分支与字段全部带 default，v2 工程直接读入——沿用 serial_master 时的兼容模式）。

## 四、引擎（netlink-core/src/protocol/can/）

### 4.1 帧与 IO 抽象

```rust
pub struct CanFrame { pub id: u32, pub extended: bool, pub remote: bool, pub data: Vec<u8> }

pub trait CanIo: Send {
    fn send(&mut self, f: &CanFrame) -> Result<(), String>;
    /// None = 读超时静默（50ms 一拍，兼作调度 tick）
    fn recv(&mut self, timeout: Duration) -> Result<Option<CanFrame>, String>;
    /// 后端错误/状态摘要（总线错误计数、bus-off 等；用于统计与徽章）
    fn status(&mut self) -> CanBusStatus;
}
```

后端实现（`usb_zlgcan.rs` / `usb_candle.rs` / `usb_slcan.rs` / `net_zlg.rs`）：

| 后端 | 路径 | 说明 |
| --- | --- | --- |
| zlgcan | zlgcan.dll FFI（VCI_OpenDevice/InitCAN/StartCAN/Transmit/Receive） | 匹配国内现场最常见的 USBCAN/CANalyst-II；**须用 x64 版驱动**（见 §八风险） |
| candle | candle API（WinUSB，candleLight 固件设备） | 开源硬件 CANable 系；驱动坑小 |
| slcan | 串口 ASCII 协议（`t<id><dlc><data>` 行式） | **直接复用现有 `serialport` 依赖**，最便携的后备路径 |
| can_net | TCP + ZLG CANET 帧编解码 | 见 4.3 |

集成测试走 `FakeCanIo`（内存队列），镜像 RTU 主机 `serve_rtu_with` 的 IO 注入模式。

### 4.2 主循环（直采直控核心，直连与以太网共用）

```
serve_can(ctx, io):
  spawn_blocking 单线程（CAN 单通道本就串行，平移 RTU 模式）:
    loop:
      ① 到期周期报文逐条 CanIo.send → FrameEvent{dir:"out", note:"ID=0x… DLC=8"}
      ② CanIo.recv(50ms) → 命中帧 → FrameEvent{dir:"in"} + CanRxStat 聚合更新
      ③ 命令通道非阻塞收取（手动发送/启停报文，插队语义同 RTU 主机）
      ④ 每 500ms：CanBusStatus + 帧率/字节率（滑动窗口）→ 连接统计推送
  链路状态：进入主循环 = Connected（复用 ConnState 推送与徽章）
```

滤波器：直采默认全收（v1 不做 UI 滤波，监视器里按 ID 过滤已有）；后端预留 acceptance filter 参数位。

### 4.3 CAN 转以太网（CanNet）

```
serve_can_net(ctx):
  连接循环（完全复用 Modbus TCP 主机模式）:
    TcpStream::connect((host, port))
      ├─ 失败/断开 → 退避重连 1s→5s→30s + ConnState(Reconnecting, 失败原因)
      └─ 成功 → ZlgCanetCodec 驱动的 CanIo 适配层 → 进入 4.2 同一主循环
  ZlgCanetCodec:
    encode(CanFrame) -> Vec<u8>      // CAN 帧封装：帧头/通道号/帧类型(标准|扩展|远程|错误)/ID/DLC/数据域
    decode(&mut BufState) -> Vec<CanFrame>  // TCP 流式缓冲 + 拆帧
  字节级布局以所选型号手册附录为准（CANET-2E 与老 CANET-100/200 协议代际不同），
  codec 独立成模块隔离差异，实现期对照官方手册样例帧写往返单测。
```

指令发送 = 同一条 `CanIo.send` 路径（手动面板/周期报文均不感知后端差异）。

## 五、UI 落点

| 位置 | 改动 |
| --- | --- |
| 连接编辑器 | 传输方式下拉 + 两类 CAN 分组字段（UsbCan：后端/设备/通道/波特率，slcan 显示串口选择+「检查串口」；CanNet：地址/端口/通道，含「测试连接」= 真实 TCP 连通测试） |
| 设备树 | CAN 连接 → CAN 节点（▶/■ 启停语义不变：停用=暂停其周期报文发送）；连接行复用链路状态徽章（重连中/断开原因悬浮） |
| 点表面板 | CAN 节点选中时显示**发送报文表**：ID/扩展/DLC/数据hex/周期/启用/备注（列形态复用现有表格；hex 编辑沿用测试帧面板的校验组件） |
| 接收观测 | 报文监视器面板加视图切换「报文流 / ID 聚合」：聚合视图 = CanRxStat 表（ID/计数/平均周期/最近数据/最后时间），自动生成不可编辑 |
| 手动发送 | 复用「测试帧」抽屉形态 → **CAN 发送面板**：ID/扩展/远程/DLC/数据 hex + 从已定义报文一键载入 + 发送 + 最近发送历史 |
| 监视器行 | note 列 = "ID=0x123 DLC=8"（扩展帧 ID 全宽显示）；hex 列 = 帧字节 |
| 采集健康 | 帧率/字节率/错误计数进连接徽章与悬浮（沿用本轮可观测性的推送链路） |

## 六、测试策略（对齐仓库既有风格：内存注入走真实路径）

1. `FakeCanIo` 内存队列驱动 4.2 主循环：周期报文按时发送（断言时序与帧内容）、监听聚合计数正确、命令插队可用；
2. slcan 编解码纯函数单测（ASCII 行 ↔ CanFrame 往返、畸形行容错）；
3. `ZlgCanetCodec` 字节级单测：encode/decode 往返 + 手册样例帧比对（实现期从手册抄录常量）；
4. TCP 端到端：本地起假 CANET server（按 codec 吐帧/收帧）驱动 `serve_can_net`，覆盖断线重连与 ConnState 推送（模式同 modbus_master.rs 测试）；
5. 工程文件序列化往返（v2 旧工程读入不丢数据）。

## 七、里程碑

| 里程碑 | 内容 | 依赖硬件 |
| --- | --- | --- |
| CAN-M1 | CanFrame/CanIo 抽象 + **slcan 后端** + 监听→监视器 + 手动发送面板 | 一台 CANable（一两百元）或任意 slcan 设备 |
| CAN-M2 | **zlgcan 后端**（FFI+波特率换算）+ CanNode/周期报文模型 + 发送报文表 + ID 聚合视图 + 总线统计 | USBCAN/CANalyst-II |
| CAN-M3 | **CanNet 半边**：ZlgCanetCodec + serve_can_net + 断线重连 + 连接编辑器/测试连接 | CANET-2E 网关 |
| v2（后置） | DBC 导入与信号解码、信号实时值表；GB/T 27930 / J1939 / CANopen 协议级模拟（视现场需要单独立规格） | — |

> M1 用 slcan 后端先行：不碰任何 FFI 与驱动，最快跑通全链路闭环；zlgcan/CANET 是对现场主流硬件的适配层，两者到货顺序可调换 M2/M3 顺序。

## 八、风险与对策

| 风险 | 对策 |
| --- | --- |
| zlgcan.dll 位数不匹配（CANalyst-II 老驱动仅 32 位，Tauri x64 进程无法加载） | 采购前确认带 **x64 驱动**；否则直采侧用 candle/Canable 设备绕开 |
| 波特率→Timing0/1 换算（ZLG 特有） | 内置 125k/250k/500k/1M 常用档位换算表；非常规波特率暴露 Timing 高级选项 |
| CANET 帧协议代际差异（CANET-100/200 vs CANET-2E） | codec 独立模块 + 手册样例帧单测；采购定型号后锁定一份字节布局 |
| 总线物理层问题（无终端电阻/不共地/波特率不匹配 → 只收错误帧） | 使用文档引导（120Ω×2、共地、波特率表）；统计面板显式展示错误帧计数帮助定位 |
| 工程文件兼容 | schema_version 3 + 全 default 字段（沿用既有兼容模式） |
| NetLink 现有 UI 概念冲突（"点表/从机地址"对 CAN 无意义） | CAN 连接下编辑器隐藏无关区块（同 Modbus 主机隐藏故障注入的先例） |

## 九、采购清单（试水成本）
