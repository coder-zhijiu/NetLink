## 一、项目定位

NetLink 是一款**多协议工业主/从机模拟器**，用于模拟各类工业与电力协议的主机（主站）与从机（设备/被控站），覆盖 Modbus、IEC 60870-5-104、DL/T 645 等协议，支持 TCP 网口与 RS-485 串口两类传输方式。

- **目标用户**：自用 + 团队内部调试（电力/工业集成、SCADA/上位机联调场景）。
- **优先级原则**：功能优先、打磨其次；架构上保留商业化余地，但不提前投入授权、加密等成本。
- **核心价值**：
  1. 模拟从机（PLC/仪表/RTU/电表/被控站），配合动态数据仿真，用于测试上位机、网关、调度系统；
  2. 模拟主机（主站/抄表端），用于轮询调试现场真实设备；
  3. 故障注入，测试通信双方的容错与健壮性。

## 二、技术选型

| 决策项 | 结论 | 关键理由 |
| --- | --- | --- |
| 软件形态 | Tauri 2 桌面应用（exe） | 同事双击即用；开发时前端 localhost 热更新；体积小 |
| 协议引擎语言 | Rust 原生（无 sidecar 进程） | 单进程单二进制；性能与长期稳定性最优 |
| Modbus 库 | `tokio-modbus` | 成熟，主从双向支持 |
| IEC 104 / DL/T 645 | 手写帧编解码 | 现成库要么 GPL（lib60870）要么质量参差；国内协议无现成可用库 |
| 前端框架 | Vue 3 + Vite + TS | H5 背景，阻力最小 |
| 点表表格 | vxe-table | 虚拟滚动 + 可编辑表格开箱即用，表格密集型工具主流选择 |
| 点表导入 | calamine（xlsx） | Rust 成熟的 xlsx 解析库 |
| 点表导出 | rust_xlsxwriter | 同上，读写闭环 |
| 串口 | serialport crate | 成熟，Windows 支持好 |
| 持久化 | 单 JSON 工程文件 | 双击分享、可进 git；几万点规模无压力 |

## 三、项目结构

Cargo workspace 三层分离，协议引擎与 UI 彻底解耦：

```
NetLink/
├── netlink-core/     # 纯 Rust 库：协议实现、点表模型、仿真引擎、持久化 schema
│   ├── protocol/     # 各协议模块（modbus / iec104 / dlt645 ...）
│   ├── sim/          # 数据仿真（波形发生器、故障注入 hook）
│   └── model/        # 工程/设备/点/点表数据模型 + JSON schema
├── netlink-app/      # Tauri 壳：commands / events，组装 core，不写业务
└── web/              # Vue 3 前端（vite + ts + vxe-table）
```

原则：`netlink-core` 不依赖 Tauri，后续 104、645 只是往 core 里填新协议模块；前端通过 Tauri command/event 与引擎交互。

## 四、MVP 范围：Modbus TCP + RTU 从机模拟

### 4.1 协议能力

- 功能码：01 / 02 / 03 / 04 / 05 / 06 / 0F / 10。
- 四区全支持：线圈、离散输入、保持寄存器、输入寄存器。
- TCP：监听端口，多连接并发；RTU：绑定真实 COM 口，波特率/校验/停止位可配。
- 虚拟串口对**不自带驱动**，应用内置文档引导安装 com0com 配对（内核驱动签名/分发成本不值得自担）。

### 4.2 数据仿真（从机灵魂）

每个点可选数据源：

- **静态值**：手动设置；
- **正弦波**：配周期/幅值/偏移；
- **斜坡/递增**：配步长/上下限回绕；
- **随机游走**：配步进范围/边界；
- **区间摆动**：min–max 往返。

全局仿真可一键暂停/恢复。

### 4.3 故障注入（三件套进 MVP）

1. 超时不响应（可配时长）；
2. 延迟响应（可配毫秒）；
3. 返回 Modbus 异常码（非法功能/非法地址/非法数据值等）。

协议处理层预留 hook 点，后续脏帧（CRC/功能码错）、主动断连、按概率丢包在 M2 补充，不回抽重构。

### 4.4 并发规模

- 按 **~50 台从机并发、每台数百点**设计性能目标；
- UI 设备树支持任意多设备（每台独立 slave id / 端口 / 点表）；
- 无分片/多进程设计；万点级需求出现时再评估（为 104 整站仿真留口）。

### 4.5 点表配置与导入导出闭环

- UI 手动配置（增删改、批量粘贴）；
- **导入**：CSV / xlsx；
- **导出**：CSV / xlsx（rust_xlsxwriter），供同事交换点表。

### 4.6 持久化

- 一个工程 = 一个 `.json` 文件（pretty 打印），含全部设备/点表/连接/仿真配置；
- 带 `schema_version` 字段，为后续迁移留路；
- 记住最近打开的工程列表。

### 4.7 UI 信息架构

三栏 + 报文监视器：

```
┌──────────────────────────────────────────────┐
│ 工具栏：连接启停 / 全局仿真暂停 / 故障开关       │
├────────────┬─────────────────────────────────┤
│ 设备树      │  点表表格                        │
│ 工程→连接   │  （在线值实时刷新、虚拟滚动、      │
│  →设备      │    单元格可直接编辑）             │
├────────────┴─────────────────────────────────┤
│ 报文监视器：时间戳 + 方向 + hex + 协议解析      │
└──────────────────────────────────────────────┘
```

- 报文监视器进 MVP（协议调试无报文等于盲调）；
- 环形缓冲保留最近约 5000 帧，可暂停 / 清空 / 按设备过滤；
- 原始帧导出功能后置。

### 4.8 主从方向

- **从机模拟先行**（承载点表、仿真、故障注入等架构资产）；
- 主机模拟（调试客户端）二阶段补充，复用同一套点表与连接配置。

## 五、里程碑路线

| 阶段 | 内容 | 关键点 |
| --- | --- | --- |
| **M1（MVP）** | Modbus TCP/RTU 从机模拟 | 点表模型、波形仿真、故障三件套、导入导出、三栏 UI、报文监视器；最小链路：点表 → 仿真引擎 → 响应上位机 → 报文上报前端 |
| **M2** | Modbus 主机模拟 + 故障增强 | 主机轮询客户端；脏帧（CRC 错）、主动断连、按概率丢包 |
| **M3** | IEC 60870-5-104 被控站模拟 | 手写 APDU/ASDU 编解码；先覆盖遥测遥信遥控遥调核心集 |
| **M4** | DL/T 645-2007 从机 + 104 主站 | 645 以 485 为主，手写帧 + 常用数据标识（电压/电流/功率/电能量，浮点/BCD/变数据标识）；104 主站侧 |

依赖关系：M1 打通的核心架构（点表模型、仿真引擎、报文管道、工程持久化）被后续所有阶段复用；每个新协议只是向 `netlink-core/protocol/` 填充新模块。

## 六、已按默认处理、可随时推翻的细节
